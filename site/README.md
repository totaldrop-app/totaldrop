# totaldrop.app

TotalDrop's website: the home page (`totaldrop.app`), downloads
(`download.totaldrop.app`), QR and share links (`totaldrop.app/r#code`) and
the privacy policy. Completely static: no cookies, no third-party requests.
Fonts are served from the site itself.

What is published is not `public/`, but the `dist/` folder built from it
([decision 0021](../docs/kararlar/0021-site-language-addresses.md)):
`node tools/build.mjs` copies `public/` as it is and writes the six pages
(home, download, roadmap, donate, team, brand) for every language under
`/<tag>/`, adding `hreflang` links and a `#languages` list at the end of
`<main>` on all 35 versions of each page. `dist/` is not committed; CI and
deployment run the same command. To try it locally, serve `dist/` with any
static file server.

## Deployment

The site is the `totaldrop` project on Cloudflare Pages. Deployment runs from
CI, from `main` only, after a maintainer approves the `cloudflare` environment
(`.github/workflows/deploy.yml`); `server/tools/probe.mjs site` then checks
the home page, the download page, translated pages on both host names and the
App Links file. Setup and rollback: [docs/surec.md](../docs/surec.md),
"Dağıtım".

## Rules

- Design follows [docs/tasarim.md](../docs/tasarim.md); the mark's animation
  is the same as in the apps.
- Add new text to the English page (with a `data-i18n` key) and to
  `i18n/en.json`, then fill in the other languages according to
  [docs/ceviri.md](../docs/ceviri.md). `node tools/check-i18n.mjs` checks all
  of them.
- After changing `styles.css`, `app.js`, `lang.js` or `msg.js`, run
  `node tools/asset-versions.mjs --write` and `node tools/privacy.mjs --write`.
  Pages ask for these files with a content hash; Cloudflare caches `.css` and
  `.js` files in the browser for 4 hours, so without a new hash visitors would
  see the new page with the old stylesheet or script (#291).
- On the six pages that have an address per language, keep the English
  `canonical` and `og:url` hand-written in the page (the build reads the
  address from there), and keep `<a class="lang-jump" href="#languages">` next
  to `#lang-select` in `<header>`. `tools/build.mjs` generates the `hreflang`
  lines, the `#languages` `<nav>` at the end of `<main>`, and the translated
  pages' `canonical` and `og:` tags; do not write those by hand. Write links
  between those pages from the root (`/roadmap/` or
  `https://totaldrop.app/roadmap/`); the build adds the language prefix, and
  `app.js` carries an explicit language choice across `totaldrop.app` and
  `download.totaldrop.app` via `?lang=<tag>` (cleaned on arrival with
  `history.replaceState`). An element with `data-i18n` holds text only. `/r`
  and the 404 page stay at a single address and are translated in the browser.
- Never add third-party resources (CDNs, analytics, font services). The CSP
  blocks them already.
- The privacy policy has its own address in every language (`/privacy`,
  `/privacy/<tag>`). Edit the text in `site/privacy/<tag>.html`, then rebuild
  the pages with `node tools/privacy.mjs --write`. The first line of each
  translation records the hash of the English text it was translated from
  (`<!-- Translated from en.html <hash>. -->`). When the English text changes,
  the hash no longer matches and CI rejects all 34 translations until they are
  updated and re-stamped, so a policy change updates all 35 languages in the
  same PR. CI also checks that every translation has the same structure as
  English (headings, paragraphs, links, `code` contents, version numbers,
  Linux paths, and every number in English) and that the generated pages are
  up to date.
- Site icons are generated from the mark. The mark's path and colours match
  across `app/assets/logo.svg`, `favicon.svg` and the constants at the top of
  `tools/favicons.mjs`. If the mark changes, update all three together, then
  regenerate `favicon.ico` and `apple-touch-icon.png` with
  `NODE_PATH=$(npm root -g) node tools/favicons.mjs --write` (requires
  Playwright) and commit them. Every page's `<head>` carries the three icon
  lines; `node tools/favicons.mjs` (CI) checks the file dimensions, the `<link>`
  lines, and that the mark matches across all three places. Google shows a
  site icon only for a square image whose side is a multiple of 48 pixels (or
  an SVG) declared with `rel="icon"` on the home page. Never add a large PNG
  as `rel="icon"`: browsers may prefer it over the SVG and lose the dark-theme
  colour.
