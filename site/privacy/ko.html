개인정보 처리방침 · 버전 6 · 2026년 11월 4일

우리는 당신에 대해 아무것도 수집하지 않습니다.

TotalDrop에는 계정, 분석, 광고, 오류 보고가 없습니다. 이 페이지는 파일을 전송하는 동안 우리 서버가 무엇을 볼 수 있는지, 그리고 그것이 얼마나 빨리 사라지는지를 정확히 설명합니다.

우리는 누구인가

TotalDrop은 Ozan Özdil이 관리하는 무료 오픈 소스 프로젝트입니다. 이 방침은 TotalDrop 앱, 명령줄 클라이언트, totaldrop.app의 서버에 적용됩니다. 연락처: privacy@totaldrop.app.

앱이 수집하는 것

아무것도 없습니다. 앱은 이름, 이메일 주소, 전화번호를 묻지 않으며 추적, 분석, 광고, 오류 보고 코드도 들어 있지 않습니다. 0.3.0-beta.2까지 Android 앱에 필요한 것은 인터넷 접근 권한뿐입니다. 이후 버전은 전송에 필요한 것만 요청합니다. 연결을 위한 인터넷 접근과 네트워크 상태, 다른 앱으로 전환해도 전송이 계속되도록 하는 백그라운드 전송 실행, 그리고 전송 중에 표시되는 중단 버튼이 있는 알림을 위한 알림 표시입니다. 이 권한들은 기기 안에만 머물며, 우리에게도 다른 누구에게도 아무것도 보내지 않습니다.

당신의 파일

두 기기가 서로 연결될 수 있으면 파일은 한 기기에서 다른 기기로 바로 전송되고, 그렇지 않으면 우리의 릴레이(아래 참고)를 거칩니다. 어느 경우든 파일은 종단 간 암호화됩니다. 우리 서버는 파일, 파일 이름, 내용을 절대 볼 수 없으며, 서버를 거쳐 가는 내용도 읽을 수 없습니다. 키는 두 기기에만 있기 때문입니다.

랑데부 서버가 보는 것

전송을 시작하기 위해 두 기기는 Cloudflare에서 실행되는 우리의 랑데부 서버 rendezvous.totaldrop.app에 연결합니다. 이 서버는 같은 코드를 가진 두 기기가 서로를 찾도록 돕습니다. 이 과정에서 서버는 필연적으로 다음을 봅니다.

  • 각 기기의 IP 주소(모든 인터넷 서버가 보는 것과 같습니다)
  • 코드 맨 앞의 숫자(예: 7-harbor-rocket의 7). 단어는 절대 보지 못합니다
  • 연결한 시각과 두 기기가 주고받는 짧은 메시지의 크기. 처음 두 개 이후의 메시지는 상대 기기만 읽을 수 있도록 암호화됩니다.

서버는 이 중 어느 것도 로그에 기록하지 않습니다. 메일함과 그 안의 모든 것은 두 기기가 떠나는 즉시, 늦어도 한 시간 뒤에 삭제됩니다. 전송이 끝날 때마다 코드의 숫자는 10분 동안 쉬었다가 다시 배정되며, 코드 시도가 실패한 뒤에는 24시간 동안 쉽니다.

우리의 인프라 제공자인 Cloudflare는 서비스를 제공하고 보호하기 위해 자체 개인정보 처리방침에 따라 IP 주소를 처리합니다. 릴레이도 마찬가지입니다. 우리는 두 서버 모두에서 요청 로그와 Workers 로깅을 껐습니다.

직접 경로 찾기

인터넷을 통해 연결하기 위해 각 기기는 먼저 STUN 서버에 자신이 어떤 공인 IP 주소와 포트로 보이는지 묻습니다. 기본값은 Cloudflare의 무료 STUN 서비스 stun.cloudflare.com입니다. 이 서비스는 모든 인터넷 서버처럼 당신의 IP 주소를 볼 뿐, 그 밖에는 아무것도 보지 못합니다. 개인정보 보호 모드(아래 참고)에서는 기기가 이 서비스에 묻지 않습니다.

릴레이가 보는 것

Cloudflare에서 실행되는 우리의 릴레이 relay.totaldrop.app은 두 기기가 서로 직접 연결될 수 없을 때 전송을 중계합니다. Android와 Linux 0.2.0-beta.1 이상, 그리고 2026년 10월 29일 이후 저장소에서 빌드한 명령줄에서는, 두 기기가 연결을 시작한 지 약 1.2초가 지나도 직접 연결이 선택되지 않은 경우에만 기기가 릴레이에 연결합니다. 두 기기 중 하나가 개인정보 보호 모드이거나 상대 기기가 주소를 하나도 알리지 않으면 즉시 릴레이에 연결합니다. 직접 연결이 제때 선택된 전송은 그 연결이 나중에 조용해질 때만 릴레이에 도달합니다. 0.3.0-beta.3 이후의 Android 및 Linux 버전과 함께 제공되는 명령줄에서는, 네트워크가 끊기거나 상대 기기가 일시 중지되어 직접 연결로 상대 기기에서 8초 동안 아무것도 받지 못한 기기가 전송을 릴레이로 옮기고, 직접 연결에서 다시 무언가를 받는 즉시 직접 연결로 되돌립니다. 이는 두 기기가 같은 릴레이를 사용할 때만 일어납니다. 직접 연결이 나중에 선택되면 기기는 그 순간 릴레이 연결을 닫습니다. 이전 버전(Android 0.1.0-beta.5, Linux 0.1.0-beta.4)은 모든 전송을 시작할 때 릴레이에 연결하며, 이 버전의 수신 기기는 보내는 사람이 지정한 릴레이를 그대로 사용합니다. 이를 막으려면 업데이트하세요. 릴레이가 사용되면 릴레이는 다음을 봅니다.

  • 각 기기의 IP 주소
  • 이번 전송만을 위해 만들어지고 다시는 쓰이지 않는 무작위 키 두 개
  • 각 기기가 연결하고 연결을 끊은 시각, 그리고 지나간 암호화된 데이터의 양

키는 한 전송을 다른 전송과 연결하지 않지만, IP 주소는 연결할 수 있습니다. 릴레이와 랑데부 서버는 둘 다 우리가 Cloudflare에서 운영하며, 몇 순간 차이로 당신의 IP 주소를 보기 때문입니다. 릴레이는 파일, 파일 이름, 당신이 누구인지에 관한 어떤 것도 읽을 수 없습니다. 아무것도 로그에 기록하지 않으며, 전송이 끝나면 그 전송에 관한 어떤 것도 보관하지 않습니다.

각 기기의 릴레이 주소는 암호화된 상태로 상대 기기에 공유됩니다. 보내는 사람이 자체 릴레이(명령줄의 --relay 옵션 또는 TOTALDROP_RELAY)를 사용하는 경우, 0.2.0-beta.1 이상의 수신 기기는 그것이 받는 사람 자신의 릴레이 설정과 같을 때만 사용하고, 그렇지 않으면 절대 연결하지 않습니다. 기기가 연결하는 릴레이를 운영하는 사람은 위에 나열된 내용을 봅니다. 두 기기가 서로 다른 릴레이를 사용하고 직접 경로도 없으면 전송은 오류와 함께 중단됩니다.

개인정보 보호 모드(0.2.0-beta.1부터 앱 설정의 "상대 기기에 내 주소 숨기기", 명령줄의 --relay-only): 기기는 상대 기기에 IP 주소를 전혀 알리지 않고, STUN 서버에 묻지 않으며, 상대 기기에 직접 연결하지 않고, 페어링된 기기의 직접 연결도 거부합니다. 모든 전송이 릴레이를 거치므로, 보내든 받든 상대 기기는 당신의 IP 주소를 알 수 없습니다. 속도는 느려지며, 릴레이와 랑데부 서버는 여전히 당신의 IP 주소를 봅니다. 보내든 받든 상대 기기는 당신과 같은 릴레이를 사용해야 합니다(모든 앱은 우리 릴레이를 사용합니다). 그렇지 않으면 전송은 오류와 함께 중단됩니다.

상대 기기가 보는 것

직접 연결하기 위해 두 기기는 서로의 네트워크 주소를 암호화해 주고받습니다. 따라서 모든 직접 연결과 마찬가지로 각 기기는 상대 기기의 로컬 IP 주소와 공인 IP 주소를 알게 됩니다. 개인정보 보호 모드인 기기는 주소를 하나도 알리지 않으므로 상대 기기는 그 주소를 알 수 없습니다.

당신의 기기에서

받은 파일은 Android에서는 Download/TotalDrop에, Linux에서는 ~/Downloads/TotalDrop에 저장됩니다. 이 파일들은 일반 공유 파일이며 다른 다운로드와 똑같이 취급됩니다. Android에서 보낼 때 선택한 파일은 앱의 캐시에 복사됩니다. 복사본은 완료된 보내기를 닫거나 보내기를 중단하면 삭제됩니다. 선택했지만 보내지 않은 파일(보내기 전에 뒤로 갔거나, 목록에서 뺐거나, Android가 앱을 종료한 경우)의 복사본은 이후의 보내기가 닫히거나 중단될 때까지, 또는 Android가 캐시를 지울 때까지 남아 있을 수 있습니다. 앱은 두 가지 설정을 저장합니다. 랑데부 서버의 주소와 개인정보 보호 모드가 켜져 있는지 여부입니다(Linux에서는 ~/.config/totaldrop/settings.toml). Android 앱 자체의 데이터, 즉 이 복사본과 설정은 클라우드 백업이나 기기 간 데이터 이전에 절대 포함되지 않습니다.

아동

TotalDrop은 아동을 대상으로 하지 않으며 누구에게서도 개인 데이터를 수집하지 않습니다.

당신의 권리

우리는 당신에 관한 개인 데이터를 전혀 보유하지 않으므로 열람, 정정, 삭제할 것이 없습니다. 질문이나 불만이 있으면 위 주소로 연락해 주세요. 당신에게는 개인정보 보호 감독기관에 불만을 제기할 권리도 있습니다.

변경 사항

버전 6은 조용해진 직접 연결을 다시 응답이 올 때까지 릴레이로 옮기는 0.3.0-beta.3 이후의 Android 및 Linux 버전을 반영합니다. 따라서 릴레이가 직접 연결로 시작된 전송을 볼 수 있습니다. 버전 5는 0.3.0-beta.2 이후의 Android 버전이 요청하는 권한을 나열합니다. 이 권한 덕분에 전송은 알림과 함께 백그라운드에서 계속될 수 있으며, 우리 서버가 보는 것은 달라지지 않습니다. 버전 4는 릴레이와 상대 기기가 보는 것을 바꾼 Android와 Linux 0.2.0-beta.1을 반영합니다. 이 버전들에서 기기는 모든 전송을 시작할 때가 아니라, 직접 연결이 제때 선택되지 않거나 시도할 직접 경로가 없을 때만 릴레이에 연결합니다. 받는 사람은 더 이상 보내는 사람만 선택한 릴레이를 사용하지 않으므로, 이제 개인정보 보호 모드는 받는 사람의 주소도 숨깁니다. 개인정보 보호 모드는 이제 앱 설정에도 있으며 직접 연결을 거부합니다. 버전 4는 Android 앱이 캐시에 무엇을 보관하는지도 설명합니다. 버전 3은 버전 2를 바로잡았습니다. 버전 2는 앱이 어떤 직접 경로도 작동하지 않을 때만 릴레이에 연결한다고(당시에는 모든 전송을 시작할 때 릴레이에 연결했습니다), 그리고 개인정보 보호 모드가 받는 사람의 주소를 숨긴다고(당시에는 숨기지 않았습니다) 했습니다. 버전 3은 Linux 앱의 파일도 명시했습니다. 버전 2는 STUN 서비스와 릴레이를 추가했습니다. 이후 버전에 계획된 기능(링크, 선택형 익명 계정)은 우리 서버가 처리하는 것을 바꿀 것입니다. 그런 기능을 출시하기 전에 이 방침을 업데이트하고, 모든 버전을 프로젝트의 공개 저장소에 보관하겠습니다.
