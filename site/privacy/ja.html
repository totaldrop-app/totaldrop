プライバシーポリシー · 第 8 版 · 2026 年 11 月 13 日

あなたについてほとんど何も収集しません。

TotalDrop にはアカウントも、アクセス解析やトラッキングコードも、広告も、クラッシュレポートもありません。このページでは、ファイルを転送している間に私たちのサーバーと、それを運用する Cloudflare が何を見られるのか、そしてそれがどれだけ早く消えるのかを正確に説明します。

私たちについて

TotalDrop は Ozan Özdil が運営する無料のオープンソースプロジェクトです。このポリシーは、TotalDrop アプリ、コマンドラインクライアント、totaldrop.app のサーバーに適用されます。連絡先: privacy@totaldrop.app。

アプリが収集するもの

何もありません。アプリは名前、メールアドレス、電話番号を尋ねず、トラッキング、アクセス解析、広告、クラッシュレポートのコードも含みません。0.3.0-beta.2 までの Android アプリに必要なのはインターネットへのアクセスだけです。それ以降のバージョンは、転送に必要なものだけを求めます。接続のためのインターネットへのアクセスとネットワークの状態、別のアプリに切り替えても転送が続くようにするためのバックグラウンドでの転送の実行、そして転送中に表示される「中止」ボタン付きの通知のための通知の表示です。これらの権限はあなたのデバイスの中にとどまり、私たちにも他の誰にも何も送信しません。

あなたのファイル

2 台のデバイスが互いに到達できる場合、ファイルは一方のデバイスからもう一方へ直接送られ、そうでない場合は私たちのリレー(後述)を経由します。どちらの場合もエンドツーエンドで暗号化されます。私たちのサーバーがあなたのファイル、その名前や内容を見ることはなく、サーバーを通過するものを読むこともできません。鍵は 2 台のデバイスにしか存在しないからです。

ランデブーサーバーが見るもの

転送を始めるため、両方のデバイスは Cloudflare 上で動作する私たちのランデブーサーバー rendezvous.totaldrop.app に接続します。このサーバーは、同じコードを共有する 2 台のデバイスが互いを見つけるのを助けます。その際、次のものが必然的に見えます。

  • 各デバイスの IP アドレス(どのインターネットサーバーでも見えるものです)
  • コードの先頭の数字(たとえば 7-harbor-rocket の 7)。ただし単語は決して見えません
  • 接続した時刻と、2 台のデバイスがやり取りする短いメッセージのサイズ。最初の 2 通の後、これらのメッセージは相手のデバイスだけが読めるよう暗号化されます。

サーバーはこれらを一切ログに書き込みません。メールボックスとその中身は、両方のデバイスが離れるとすぐに、遅くとも 1 時間後には削除されます。転送が終わるたびに、コードの数字は 10 分間休ませてから再び割り当てられます。コードの入力に失敗した場合は 24 時間です。不正利用を抑えるため、サーバーは各 IP アドレスが開く接続の数も数えます(IPv6 ではアドレスの先頭 64 ビット)。この数はメモリ内にだけ保持され、アドレスそのものではなく、ランダムな鍵でアドレスから作ったコードで管理されます。最後の接続から遅くともおよそ 2 分後に忘れられ、ディスクやログに書き込まれることはありません。

インフラ提供者である Cloudflare は、サービスを提供し保護するために、自社のプライバシーポリシーに基づいて IP アドレスを処理します。リレーについても同じです。私たちは両方のサーバーでリクエストログと Workers のログ記録を無効にしています。それでも Cloudflare が保持するものについては、下の「Cloudflare が保持するもの」で説明します。

直接の経路を見つける

インターネット越しに接続するため、各デバイスはまず STUN サーバーに、自分がどのパブリック IP アドレスとポートで見えているかを尋ねます。既定では、これは Cloudflare の無料 STUN サービス stun.cloudflare.com です。このサービスにはどのインターネットサーバーとも同じくあなたの IP アドレスが見えますが、それ以外は何も見えません。プライバシーモード(後述)では、デバイスはこのサービスに問い合わせません。

リレーが見るもの

Cloudflare 上で動作する私たちのリレー relay.totaldrop.app は、2 台のデバイスが直接到達できないときに転送を中継します。Android と Linux の 0.2.0-beta.1 以降、および 2026 年 10 月 29 日以降にリポジトリからビルドしたコマンドラインでは、2 台のデバイスが接続を始めてから約 1.2 秒経っても直接接続が選ばれていない場合にのみ、デバイスはリレーに接続します。どちらかのデバイスがプライバシーモードのとき、または相手のデバイスがアドレスを一つも知らせないときは、すぐにリレーに接続します。直接接続が間に合って選ばれた転送がリレーに届くのは、その接続が後で途絶えた場合だけです。0.3.0-beta.3 より後の Android と Linux のバージョンと、それに付属するコマンドラインでは、ネットワークが切れた、または相手のデバイスが一時停止したために、直接接続で相手から 8 秒間何も届かなかったデバイスは、転送をリレーに移します。相手のデバイスがまだ直接接続で送っている場合にだけ直接接続に戻り、そうでなければ転送は終わるまでリレーにとどまります。これは両方のデバイスが同じリレーを使っている場合にだけ起こります。直接接続が後から選ばれた場合、デバイスはその時点でリレーとの接続を閉じます。古いバージョン(Android 0.1.0-beta.5、Linux 0.1.0-beta.4)はすべての転送の開始時にリレーに接続し、それらのバージョンの受信側デバイスは送信者が指定したリレーをそのまま使います。これをやめるにはアップデートしてください。リレーが使われる場合、リレーに見えるのは次のものです。

  • 各デバイスの IP アドレス
  • この転送のためだけに作られ、二度と使われない 2 つのランダムな鍵
  • 各デバイスが接続・切断した時刻と、通過した暗号化データの量

鍵によって転送どうしが結び付くことはありませんが、IP アドレスによって結び付く可能性はあります。リレーとランデブーサーバーはどちらも私たちが Cloudflare 上で運用しており、あなたの IP アドレスをほぼ同時に見るからです。リレーはファイル、その名前、あなたが誰かを示すものを一切読めません。何もログに書き込まず、転送が終わればその転送について何も保持しません。不正利用を抑えるため、Cloudflare は各 IP アドレスがリレーに開く接続の数を数えます。10 秒間に 30 を超える接続を開いたアドレスは、10 秒間拒否されます。

各デバイスのリレーのアドレスは、暗号化された状態で相手のデバイスに伝えられます。送信者が独自のリレー(コマンドラインの --relay オプションまたは TOTALDROP_RELAY)を使う場合、0.2.0-beta.1 以降の受信側デバイスは、それが受信者自身のリレー設定と同じときにだけ使い、そうでなければ一切接続しません。デバイスが接続するリレーを運用している人には、上に挙げたものが見えます。2 台のデバイスが別々のリレーを使っていて直接の経路もない場合、転送はエラーで止まります。

プライバシーモード(0.2.0-beta.1 以降のアプリの設定にある「相手のデバイスに自分のアドレスを隠す」、コマンドラインでは --relay-only): あなたのデバイスは相手のデバイスに IP アドレスを一切知らせず、STUN サーバーにも問い合わせず、相手のデバイスに直接接続することもなく、ペアになったデバイスからの直接接続さえ拒否します。すべての転送がリレーを通るため、送信でも受信でも、相手のデバイスにあなたの IP アドレスは知られません。速度は遅くなり、リレーとランデブーサーバーには引き続きあなたの IP アドレスが見えます。送信でも受信でも、相手のデバイスはあなたと同じリレーを使う必要があります(アプリはすべて私たちのリレーを使います)。そうでなければ転送はエラーで止まります。

Cloudflare が保持するもの

Cloudflare はこのウェブサイトと両方のサーバーを運用しています。ログ記録を無効にしていても、totaldrop.app とそのサブドメイン(このウェブサイト、ランデブーサーバー、リレーを含む)へのリクエストのサンプルを保持し、そのサンプルを自社のダッシュボードで私たちに表示します。サンプル内の各リクエストについて、次のものを記録します。

  • IP アドレスと、その接続元の国とネットワーク
  • 時刻、リクエストされた URL、送り返されたデータの量。ランデブーサーバーではその URL にコードの数字が、リレーでは転送の二つの鍵が含まれるため、サンプルから二つの IP アドレスが同じ転送に関わったことがわかる場合があります。
  • 接続の技術的な詳細(ブラウザーやプログラムが名前を送る場合は、その名前など)

どのリクエストをサンプルに入れるかは Cloudflare が選び、サンプルは 31 日間保持されます。これはどのプランでも同じで、無効にする設定はありません。上記のリレーの制限のように、セキュリティルールが拒否したリクエストも、IP アドレスとともに 31 日間保持されます。私たちがこれらの記録を見るのは不正利用や障害に対処するときだけで、ほかの場所にコピーすることはありません。

相手のデバイスが見るもの

直接接続するため、2 台のデバイスは互いのネットワークアドレスを暗号化してやり取りします。そのため、どの直接接続とも同じく、各デバイスは相手のローカル IP アドレスとパブリック IP アドレスを知ることになります。プライバシーモードのデバイスはアドレスを一つも知らせないので、相手のデバイスがそれを知ることはありません。

あなたのデバイス上

受信したファイルは、Android では Download/TotalDrop に、Linux では ~/Downloads/TotalDrop に保存されます。これらは通常の共有ファイルで、ほかのダウンロードと同じように扱われます。Android から送信すると、選んだファイルはアプリのキャッシュにコピーされます。コピーは、完了した送信を閉じたとき、または送信を中止したときに削除されます。選んだものの送信しなかったファイル(送信前に戻った、リストから外した、または Android がアプリを終了した)のコピーは、後の送信が閉じられるか中止されるまで、または Android がキャッシュを消去するまで残ることがあります。アプリが保存する設定は 2 つです。ランデブーサーバーのアドレスと、プライバシーモードがオンかどうかです(Linux では ~/.config/totaldrop/settings.toml)。Android アプリ自身のデータ、つまりこれらのコピーと設定が、クラウドバックアップやデバイス間のデータ移行に含まれることはありません。

子ども

TotalDrop は子どもを対象としておらず、誰にも個人データを求めません。

あなたの権利

上で説明した、数分で消える短期間の数と、31 日後に消える Cloudflare の記録を除き、私たちはあなたに関する個人データを一切保持していません。これらの記録にある IP アドレスから、あなたが誰なのかはわかりません。質問、苦情、またはご自身のデータに関する要望がある場合は、上記のアドレスまでご連絡ください。あなたにはデータ保護当局に苦情を申し立てる権利もあります。

変更履歴

第 8 版では、Cloudflare が保持するものを記しています。IP アドレスとコードの数字またはリレーの鍵を含むリクエストのサンプル(私たちは 31 日間見ることができます)と、そのセキュリティルールが拒否したリクエストです。また、10 秒間に 30 を超える接続を開いた IP アドレスをリレーが拒否することも記しています。第 7 版では、ランデブーサーバーが不正利用を抑えるために各 IP アドレスの接続を短い間、メモリ内でだけ数えることを記しています。サーバーが見るものは変わりません。第 6 版は、途絶えた直接接続をリレーに移す 0.3.0-beta.3 より後の Android と Linux のバージョンに合わせたものです。そのため、直接接続で始まった転送をリレーが見ることがあります。第 5 版では、0.3.0-beta.2 より後の Android バージョンが求める権限を記載しています。これらの権限により、転送は通知を表示したままバックグラウンドで続行できます。私たちのサーバーに見えるものは変わりません。第 4 版は、リレーと相手のデバイスに見えるものを変えた Android と Linux の 0.2.0-beta.1 に合わせたものです。これらのバージョンでは、デバイスはすべての転送の開始時ではなく、直接接続が間に合って選ばれないとき、または試せる直接の経路がないときにだけリレーに接続します。受信者は送信者だけが選んだリレーを使わなくなったため、プライバシーモードは受信者のアドレスも隠すようになりました。プライバシーモードはアプリの設定にも加わり、直接接続を拒否します。第 4 版では、Android アプリがキャッシュに何を保持するかも説明しています。第 3 版は第 2 版を訂正しました。第 2 版には、アプリは直接の経路がどれも使えないときにだけリレーに接続する(実際には当時はすべての転送の開始時に接続していました)、またプライバシーモードは受信者のアドレスを隠す(当時は隠していませんでした)と書かれていました。第 3 版では Linux アプリのファイルも明記しました。第 2 版では STUN サービスとリレーを追加しました。今後のバージョンで予定している機能(リンク、任意の匿名アカウント)によって、私たちのサーバーが扱うものは変わります。そうした機能を公開する前にこのポリシーを更新し、すべての版をプロジェクトの公開リポジトリに残します。
