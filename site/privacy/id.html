Kebijakan privasi · versi 5 · 3 November 2026

Kami tidak mengumpulkan apa pun tentang Anda.

TotalDrop tidak punya akun, analitik, iklan, maupun laporan kerusakan. Halaman ini menjelaskan dengan tepat apa yang dapat dilihat server kami saat Anda mentransfer file, dan seberapa cepat semuanya hilang.

Siapa kami

TotalDrop adalah proyek sumber terbuka gratis yang dikelola oleh Ozan Özdil. Kebijakan ini berlaku untuk aplikasi TotalDrop, klien baris perintah, dan server di totaldrop.app. Kontak: privacy@totaldrop.app.

Apa yang dikumpulkan aplikasi

Tidak ada. Aplikasi tidak meminta nama, alamat email, atau nomor telepon Anda, dan tidak berisi kode pelacakan, analitik, iklan, atau laporan kerusakan. Hingga 0.3.0-beta.2, aplikasi Android hanya memerlukan akses internet. Versi berikutnya hanya meminta yang dibutuhkan untuk transfer: akses internet dan status jaringan, untuk terhubung; menjalankan transfer di latar belakang, agar tetap berjalan saat Anda beralih ke aplikasi lain; dan menampilkan notifikasi, untuk notifikasi berkelanjutan dengan tombol Hentikan selama transfer berjalan. Izin-izin ini tetap di perangkat Anda: izin tersebut tidak mengirim apa pun kepada kami atau siapa pun.

File Anda

File berpindah langsung dari satu perangkat ke perangkat lain jika keduanya dapat saling menjangkau, dan jika tidak, melalui relay kami (di bawah); bagaimanapun juga, file dienkripsi secara end-to-end. Server kami tidak pernah melihat file Anda, namanya, atau isinya, dan tidak dapat membaca apa yang melewatinya: kuncinya hanya ada di kedua perangkat.

Apa yang dilihat server pertemuan

Untuk memulai transfer, kedua perangkat terhubung ke server pertemuan kami di rendezvous.totaldrop.app, yang berjalan di Cloudflare. Server ini membantu dua perangkat yang memiliki kode yang sama untuk saling menemukan. Saat melakukannya, server ini mau tidak mau melihat:

  • alamat IP setiap perangkat, seperti server internet mana pun;
  • angka di awal kode (misalnya 7 pada 7-harbor-rocket), tetapi tidak pernah kata-katanya;
  • kapan Anda terhubung dan ukuran pesan singkat yang dipertukarkan kedua perangkat. Setelah dua pesan pertama, pesan-pesan ini dienkripsi sehingga hanya perangkat lain yang dapat membacanya.

Server tidak mencatat semua ini ke dalam log. Kotak surat beserta seluruh isinya dihapus segera setelah kedua perangkat pergi, dan paling lambat setelah satu jam. Setelah setiap transfer, angka kode diistirahatkan selama 10 menit sebelum diberikan lagi; setelah percobaan kode yang gagal, selama 24 jam.

Cloudflare, sebagai penyedia infrastruktur kami, memproses alamat IP untuk menghadirkan dan melindungi layanan berdasarkan kebijakan privasinya sendiri. Hal yang sama berlaku untuk relay. Kami telah menonaktifkan log permintaan dan logging Workers untuk kedua server.

Menemukan jalur langsung

Untuk terhubung melalui internet, setiap perangkat terlebih dahulu menanyakan kepada server STUN alamat IP publik dan port apa yang terlihat darinya. Secara bawaan, ini adalah layanan STUN gratis dari Cloudflare di stun.cloudflare.com. Layanan ini melihat alamat IP Anda, seperti server internet mana pun, dan tidak ada yang lain. Dalam mode privasi (di bawah), perangkat tidak menanyakannya.

Apa yang dilihat relay

Relay kami di relay.totaldrop.app, yang berjalan di Cloudflare, membawa transfer ketika kedua perangkat tidak dapat saling menjangkau secara langsung. Di Android dan Linux 0.2.0-beta.1 dan yang lebih baru, serta di baris perintah yang dibangun dari repositori sejak 29 Oktober 2026, perangkat hanya menghubungi relay jika belum ada koneksi langsung yang dipilih sekitar 1,2 detik setelah kedua perangkat mulai terhubung. Perangkat langsung menghubungi relay jika salah satu perangkat dalam mode privasi atau perangkat lain tidak mengumumkan alamat apa pun. Transfer yang koneksi langsungnya dipilih tepat waktu tidak pernah mencapai relay. Jika koneksi langsung dipilih belakangan, perangkat menutup koneksi relay-nya saat itu juga. Versi lama (Android 0.1.0-beta.5, Linux 0.1.0-beta.4) terhubung ke relay di awal setiap transfer, dan perangkat penerima dengan versi tersebut menggunakan relay mana pun yang disebutkan pengirim; perbarui untuk menghentikan hal ini. Ketika relay digunakan, relay melihat:

  • alamat IP setiap perangkat;
  • dua kunci acak yang dibuat khusus untuk transfer ini dan tidak pernah digunakan lagi;
  • kapan setiap perangkat terhubung dan terputus, serta berapa banyak data terenkripsi yang lewat.

Kunci tidak menghubungkan satu transfer dengan transfer lain, tetapi alamat IP Anda bisa: relay dan server pertemuan, keduanya dijalankan oleh kami di Cloudflare, melihatnya dalam selang beberapa saat. Relay tidak dapat membaca file, namanya, atau apa pun tentang siapa Anda. Relay tidak mencatat apa pun ke log dan tidak menyimpan apa pun tentang transfer setelah transfer selesai.

Alamat relay setiap perangkat dibagikan ke perangkat lain dalam keadaan terenkripsi. Jika pengirim menggunakan relay sendiri (opsi --relay pada baris perintah atau TOTALDROP_RELAY), mulai 0.2.0-beta.1 perangkat penerima hanya menggunakannya jika relay itu juga merupakan setelan relay milik penerima; jika tidak, perangkat penerima tidak pernah menghubunginya. Siapa pun yang menjalankan relay yang dihubungi sebuah perangkat dapat melihat hal-hal yang disebutkan di atas. Ketika kedua perangkat menggunakan relay yang berbeda dan tidak memiliki jalur langsung, transfer berhenti dengan kesalahan.

Mode privasi ("Sembunyikan alamat saya dari perangkat lain" di Setelan aplikasi sejak 0.2.0-beta.1, --relay-only di baris perintah): perangkat Anda tidak mengumumkan alamat IP kepada perangkat lain, tidak bertanya ke server STUN, tidak pernah menghubungi perangkat lain secara langsung, dan menolak koneksi langsung bahkan dari perangkat yang dipasangkan. Setiap transfer melewati relay, sehingga perangkat lain tidak mengetahui alamat IP Anda, baik saat Anda mengirim maupun menerima. Cara ini lebih lambat, dan relay serta server pertemuan tetap melihat alamat IP Anda. Perangkat lain harus menggunakan relay yang sama dengan Anda, baik saat Anda mengirim maupun menerima (semua aplikasi menggunakan relay kami); jika tidak, transfer berhenti dengan kesalahan.

Apa yang dilihat perangkat lain

Untuk terhubung langsung, kedua perangkat saling bertukar alamat jaringan dalam keadaan terenkripsi. Karena itu, setiap perangkat mengetahui alamat IP lokal dan publik perangkat lainnya, seperti pada setiap koneksi langsung. Perangkat dalam mode privasi tidak mengumumkan alamat apa pun, sehingga perangkat lain tidak mengetahuinya.

Di perangkat Anda

File yang diterima disimpan di Download/TotalDrop di Android dan di ~/Downloads/TotalDrop di Linux. File tersebut adalah file bersama biasa, yang diperlakukan seperti unduhan Anda lainnya. Saat Anda mengirim dari Android, file yang Anda pilih disalin ke cache aplikasi. Salinan dihapus saat Anda menutup pengiriman yang telah selesai atau menghentikannya. Salinan file yang Anda pilih tetapi tidak Anda kirim (Anda kembali sebelum mengirim, menghapusnya dari daftar, atau Android menutup aplikasi) dapat tetap ada sampai pengiriman berikutnya ditutup atau dihentikan, atau sampai Android membersihkan cache. Aplikasi menyimpan dua setelan: alamat server pertemuan dan apakah mode privasi aktif (di Linux dalam ~/.config/totaldrop/settings.toml). Data milik aplikasi Android sendiri, yaitu salinan dan setelan ini, tidak pernah masuk ke cadangan cloud atau transfer antarperangkat.

Anak-anak

TotalDrop tidak ditujukan untuk anak-anak dan tidak mengumpulkan data pribadi dari siapa pun.

Hak Anda

Karena kami tidak menyimpan data pribadi apa pun tentang Anda, tidak ada yang perlu diakses, dikoreksi, atau dihapus. Jika Anda punya pertanyaan atau keluhan, tulis kepada kami di alamat di atas. Anda juga berhak mengajukan keluhan kepada otoritas pelindungan data.

Perubahan

Versi 5 mencantumkan izin yang diminta versi Android setelah 0.3.0-beta.2, yang memungkinkan transfer berlanjut di latar belakang dengan notifikasi; apa yang dilihat server kami tidak berubah. Versi 4 mengikuti Android dan Linux 0.2.0-beta.1, yang mengubah apa yang dilihat relay dan perangkat lain. Pada versi ini, perangkat hanya menghubungi relay jika tidak ada koneksi langsung yang dipilih tepat waktu atau tidak ada jalur langsung untuk dicoba, bukan di awal setiap transfer. Penerima tidak lagi menggunakan relay yang hanya dipilih pengirim, sehingga mode privasi kini juga menyembunyikan alamat penerima. Mode privasi kini juga ada di Setelan aplikasi dan menolak koneksi langsung. Versi 4 juga menyebutkan apa yang disimpan aplikasi Android di cache-nya. Versi 3 mengoreksi versi 2, yang menyatakan bahwa aplikasi hanya menghubungi relay jika tidak ada jalur langsung yang berhasil (saat itu aplikasi terhubung ke relay di awal setiap transfer) dan bahwa mode privasi menyembunyikan alamat penerima, padahal saat itu belum. Versi 3 juga menyebutkan file aplikasi Linux. Versi 2 menambahkan layanan STUN dan relay. Fitur yang direncanakan untuk versi mendatang (tautan, akun anonim opsional) akan mengubah apa yang diproses server kami. Kami akan memperbarui kebijakan ini sebelum fitur semacam itu dirilis, dan menyimpan setiap versinya di repositori publik proyek.
