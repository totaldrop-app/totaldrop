# TotalDrop for Android (Flutter)

The Android application lives here (and later iOS; Linux lives in [`linux/`](../linux), and Windows will live in `windows/` per [decision 0006](../docs/kararlar/0006-linux-qt.md) and [decision 0016](../docs/kararlar/0016-windows-microsoft-store.md)). It is a thin interface over the shared Rust workspace, reached through `flutter_rust_bridge`.

## Layout

- `lib/` — Flutter UI (`lib/ui/`, including zero-dependency `DisplayFeature` foldable and large-screen layouts in `lib/ui/core/adaptive.dart`), data repositories (`lib/data/`), generated localizations (`lib/l10n/`) and generated Rust bindings (`lib/src/rust/`).
- `android/` — Android host (`applicationId = "app.totaldrop"`, `minSdk = 35` / Android 15+, `compileSdk = 37`, `useLegacyPackaging = false` so native `.so` libraries are stored uncompressed at 16 KB APK boundaries alongside Cargokit's `-Wl,-z,max-page-size=16384` ELF `PT_LOAD` alignment): share and multi-window drag-and-drop copying (`SharedFiles.kt`), user-initiated background transfer job (`TransferJob.kt`, [decision 0010](../docs/kararlar/0010-android-arka-plan-aktarim.md)), OEM battery guidance (`BackgroundAccess.kt`) and link/shortcut/drag routing (`MainActivity.kt`, `Launches.kt`).
- `rust/` — `rust_lib_totaldrop` bridge crate (`rust/src/api/transfer.rs`, `rust/src/api/l10n.rs`) calling `totaldrop-core`, `totaldrop-proto` and `totaldrop-l10n`.
- `rust_builder/` — Cargokit build integration invoked by Gradle/Flutter.
- `tool/` — Generators for `locales_config.xml` and Android `res/values*/l10n.xml` from [`../l10n/app/`](../l10n/app), plus `check_16kb_elf.py` for 16 KB `PT_LOAD` and APK alignment verification.
- `test/` — Dart and widget tests (including 35-locale layout, foldable postures, RTL static analysis and Material 3 Expressive checks); Kotlin JVM unit tests live under `android/app/src/test/`.

## Rules for this directory

- **No cryptography or protocol parsing in Dart or Kotlin.** Keys, hashes, signatures, transfer codes and wire messages stay in the Rust crates.
- **No analytics, crash reporters, proprietary Play Services ML/vision SDKs or advertising SDKs, ever.**
- **Network access only through the Rust core**, so privacy mode can route everything through the relay (and later Tor).
- **Cross-app share and multi-window Drag & Drop trust boundary:** `MainActivity.kt` ignores in-app drags (`event.localState != null`), reads `ClipData.Item.uri` / `ClipData.Item.text` directly (never `coerceToText`), acquires `DragAndDropPermissions` and releases it on all exit paths once `ShareCopier` finishes copying into app-private cache, and enforces `SharedFiles.acceptable` (`content://` only, excluding own authority/package, readable files) before handing paths to `SendViewModel`. Active transfers and unsaved received texts block incoming shares and drops in `LaunchRouter`.
- **Design and motion:** Material You dynamic colour with the Aurora fallback, zero elevation ([decision 0011](../docs/kararlar/0011-android-material-3-expressive.md)), and the `Köşe` mark motion matching [`docs/tasarim.md`](../docs/tasarim.md).
- **Generated files** (`lib/l10n/`, `lib/src/rust/`, `rust/src/frb_generated.rs`, `android/app/src/main/res/xml/locales_config.xml`, `android/app/src/main/res/values*/l10n.xml`) are regenerated by their tools, never edited by hand.

## Local checks

Run the same checks as [`.github/workflows/android.yml`](../.github/workflows/android.yml):

```sh
cd app
flutter pub get --enforce-lockfile
flutter gen-l10n
dart run tool/gen_locales_config.dart
dart run tool/gen_android_strings.dart
git add -N android/app/src/main/res
git diff --exit-code -- lib/l10n android/app/src/main/res/xml/locales_config.xml 'android/app/src/main/res/values*/l10n.xml'
flutter analyze
find lib test tool -name '*.dart' -not -path 'lib/l10n/*' -not -path 'lib/src/rust/*' -print0 |
  xargs -0 dart format --output=none --set-exit-if-changed
flutter test
python3 -m unittest discover -s tool -p 'test_*.py' -v
(cd .. && cargo test -p rust_lib_totaldrop --locked)
```

With the Android SDK and JDK 21 installed, build the debug APK, verify 16 KB ELF/APK alignment, and run the Kotlin JVM unit tests:

```sh
cd app
flutter build apk --debug --target-platform android-arm64
python3 tool/check_16kb_elf.py --require-uncompressed build/app/outputs/flutter-apk/app-debug.apk
(cd android && ./gradlew --no-daemon :app:testDebugUnitTest)
```
